## Транзакции

| Транзакция | Описание | Тип | Компенсация |
| --- | --- | --- | --- |
| CREATE_PAYMENT | Создать запись платежа с суммой, плательщиком, получателем и начальным статусом. | компенсируемая | CANCEL_PAYMENT |
| DEBIT_CUSTOMER | Списать деньги со счета клиента. До завершения проверок деньги не переводятся контрагенту. | компенсируемая | REFUND_CUSTOMER |
| CHECK_PAYMENT | Выполнить антифрод-проверку и предусмотренные внешние проверки, включая compliance и ограничения. Антифрод может разрешить платеж, запретить его или направить на ручную проверку. | повторяемая | - |
| TRANSFER_TO_MERCHANT | Перевести деньги контрагенту после разрешения проверок или наступления cut-off. Успешный перевод является точкой невозврата этой Saga. | необратимая | - |
| COMPLETE_PAYMENT | Зафиксировать успешное завершение платежа после подтвержденного перевода. | повторяемая | - |
| REFUND_CUSTOMER | Вернуть ранее списанную сумму клиенту при отказе проверок, отмене клиентом или сбое до успешного перевода. Компенсирует списание и выполняется автоматически. | повторяемая | - |
| CANCEL_PAYMENT | Завершить платеж с неуспешным статусом и сохранить причину. Если деньги списаны, выполняется после подтвержденного возврата. Запись платежа остается для истории. | повторяемая | - |
| NOTIFY_CUSTOMER | Уведомить клиента об итоговом статусе платежа или выполненном возврате. | повторяемая | - |
| NOTIFY_SECURITY | Сообщить службе безопасности о подозрительной операции для анализа. Ошибка отправки не должна задерживать возврат денег клиенту. | повторяемая | - |

## Пояснения

- При ручной проверке платеж ожидает решения оператора до 20 минут. По условию, если ответ проверок не получен до cut-off, платеж считается разрешенным. Ожидание и таймер являются частью управления Saga, а не отдельными транзакциями.
- При отказе до перевода выполняются компенсации успешно завершенных шагов в обратном порядке: сначала возврат денег, затем отмена платежа. Если списания не было, возврат не нужен. При временной ошибке возврат повторяется автоматически до подтвержденного успеха, без ручного участия поддержки.
- Все денежные операции используют идемпотентный ключ, чтобы повтор запроса не приводил к повторному списанию, переводу или возврату. Для проверок сохраняется результат, для уведомлений исключаются дубли.
- Таймаут перевода не означает, что перевод не состоялся. Сначала нужно выяснить результат по идентификатору операции. Возврат в рамках компенсации допустим только при подтверждении, что деньги не переведены. После успешного перевода ошибки фиксации статуса и уведомлений устраняются повторными попытками, а не откатом платежа.
- Отмена клиентом или обнаружение мошенничества после успешного перевода запускают отдельный автоматический процесс возврата. Это не компенсация завершенной Saga. Детализация такого процесса в эту таблицу не входит.
