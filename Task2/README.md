# Задание 2. Таблица переходов состояний платежа

Таблица описывает Saga из задания 1: деньги списываются до проверок, а перевод контрагенту выполняется после разрешения.

## Таблица переходов

| Исходное состояние | Переходное состояние | Событие |
| --- | --- | --- |
| - | CREATED | Платеж зарегистрирован, создан экземпляр Saga. |
| CREATED | DEBITING | Начато списание средств клиента. |
| CREATED | CANCELLED | Клиент отменил платеж до начала списания, отмена сохранена. |
| DEBITING | CHECKING | Списание подтверждено, запущены антифрод и внешние проверки. |
| DEBITING | CANCELLED | Получен окончательный отказ списания, например из-за недостатка средств. Подтверждено отсутствие списания, отмена сохранена. |
| DEBITING | DEBITING | Временная ошибка или таймаут списания. Проверяется результат операции, при необходимости выполняется безопасный повтор. |
| DEBITING | REFUNDING | При обработке запроса отмены подтверждено успешное списание. Запущен автоматический возврат. |
| DEBITING | CANCELLED | При обработке запроса отмены подтверждено, что списания нет и оно больше не выполнится. Отмена сохранена. |

| CHECKING | MANUAL_REVIEW | Антифрод направил операцию на ручную проверку. Началось ожидание решения оператора. |

| CHECKING | APPROVED | Наступил cut-off проверок: окончательного ответа нет, полученных запретов нет. По условию применяется разрешение по умолчанию. |

| MANUAL_REVIEW | CHECKING | Истекли 20 минут ожидания оператора: ручная проверка разрешена по cut-off, но другие проверки еще ожидаются в пределах своего срока. |

| TRANSFERRING | TRANSFERRING | Таймаут или временная ошибка: выясняется результат перевода. Если перевод успешен, но статус не сохранен, повторяется фиксация статуса, а не перевод. |
| REFUNDING | REFUNDING | Возврат пока не подтвержден или не удалось сохранить отмену. Результат проверяется, незавершенный шаг повторяется автоматически. |
| REFUNDING | CANCELLED | Возврат подтвержден, платеж завершен с неуспешным статусом и сохраненной причиной. |

## Пояснения

- Начальное состояние - CREATED. Конечные состояния Saga: COMPLETED (деньги переведены контрагенту) и CANCELLED (списания не было либо деньги возвращены). Причина отмены и факт возврата сохраняются отдельно.
- CHECKING включает антифрод, compliance и проверки ограничений. Для автоматических проверок используется настроенный cut-off: точное время в условии не задано. Для ручного решения отводится 20 минут. Полученный запрет нельзя заменить разрешением по таймеру.
- Состояние, результаты проверок и сроки ожидания сохраняются, чтобы продолжить процесс после перезапуска. Повторные сообщения не запускают уже выполненные действия. Решение проверки, таймер и отмена обрабатываются последовательно для одного платежа, чтобы не начать перевод и возврат одновременно.
- При отмене во время списания запрос сохраняется до выяснения результата. При отмене во время перевода также сначала выясняется его результат: при окончательном отказе выполняется компенсация, при успехе запускается отдельный автоматический процесс возврата. Неизвестный результат денежной операции не считается отказом, повторы используют тот же идемпотентный ключ.
- Клиент получает уведомление об итоговом результате, служба безопасности - о подозрительной операции. Уведомления повторяются независимо от финансовых шагов и не задерживают возврат. Ошибка возврата не является конечным состоянием: автоматические попытки продолжаются без ручного участия поддержки.
- После успешного перевода отката этой Saga нет. Отмена клиентом или обнаружение мошенничества постфактум запускают отдельный автоматический процесс возврата. Поздние ответы проверок не возобновляют завершенную Saga.
